# 依赖实测计划(go/no-go 前置关卡)

## 目标
**唯一目标**:在隔离环境实测 `managed-ledger:4.1.2` 能否无冲突拉入 Kafka trunk 构建。实测结果决定后续移植策略。**本阶段不做任何移植**,只验证依赖。

## 严格隔离保证(万无一失)
1. **主仓库 `/Users/daojun/IdeaProjects/kafka` 全程不动**——不切分支、不改文件、不跑构建
2. 在 `/tmp/bk-dep-test` 创建 **detached worktree**(基于 trunk `89ccd6a126`),所有改动只发生在这个临时目录
3. 实测结束(无论成功失败)立即 `git worktree remove --force` + `prune`,彻底清理
4. 实测期间若发现冲突,只**记录**到分析报告,**不**在 worktree 里做版本调优(那是下一阶段的事)

## 实测步骤

### 步骤 1:建隔离环境
```bash
git -C /Users/daojun/IdeaProjects/kafka worktree add --detach /tmp/bk-dep-test trunk
```
失败则中止并报告。

### 步骤 2:最小化添加依赖(只加 storage 和 core 两处,与 bk-kafka 一致)
在 `/tmp/bk-dep-test` 内:
- `gradle/dependencies.gradle`:加 `managedLedger: "4.1.2"` 版本 + 坐标 `org.apache.pulsar:managed-ledger:$versions.managedLedger`
- `build.gradle`:在 `:storage` 和 `:core` 的 dependencies 块加 `implementation(libs.managedLedger) { exclude group: 'org.apache.logging.log4j', module: 'log4j-api' }`(与 bk-kafka 完全一致的写法)

### 步骤 3:依赖解析实测
```bash
cd /tmp/bk-dep-test && ./gradlew :storage:dependencies --configuration runtimeClasspath 2>&1 | tee /tmp/bk-dep-resolution.log
```
关注:
- **能否解析**(是否报 `Could not resolve`)
- **版本冲突**(gradle 会标 `(*)` 或失败;重点看 netty/protobuf/slf4j/zookeeper/guava)
- 退出码

### 步骤 4(若步骤3解析成功):编译冒烟
```bash
cd /tmp/bk-dep-test && ./gradlew :storage:compileJava 2>&1 | tee /tmp/bk-dep-compile.log
```
验证加了依赖后 storage 模块**仍能编译**(排除依赖冲突导致的编译破坏)。

### 步骤 5:清理
```bash
git -C /Users/daojun/IdeaProjects/kafka worktree remove --force /tmp/bk-dep-test
git -C /Users/daojun/IdeaProjects/kafka worktree prune
```
确认主仓库:`git -C /Users/daojun/IdeaProjects/kafka status`(应显示 trunk、clean)。
